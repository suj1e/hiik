# Spike M0 — core protocol and resize

Status: pending W1.

## Why

Two assumptions decide the whole UI:

1. `terminal.attach` returns a first paint followed by live bytes that can
   be fed straight to mygo's terminal plugin.
2. With `ResizeByConn`, sending RESIZE to the core is acknowledged by the
   core before replacement paints, so no output is laid out at the wrong
   width.

If either is wrong, the terminal pane must buffer or re-emit bytes.

## How

Run in an isolated session and home:

```sh
export HC_SESSION=hiik-test
export HIIK_HOME=$(mktemp -d)
cd apps/desktop
go run ./cmd/hiik-probe -run /bin/sh
```

Then:

1. Type `echo hello`; expect the echoed output.
2. Resize the terminal the probe is in; the probe sends RESIZE only if
   wired; for M0, add a `-resize 80x24` flag if needed.
3. Detach (Ctrl-D) and reattach with `-attach <address>`; expect the
   screen to come back.
4. Kill the terminal; expect the stream to close.

## Evidence to record

- The attach reply's `resize_notifications` and `automatic_input` values.
- Whether the core sends a resize frame, a VT repaint, or nothing after
  RESIZE.
- How many bytes of first paint arrive and whether credit is required
  before output continues.

Add the result to `LESSONS.md` and `docs/status.md`.
